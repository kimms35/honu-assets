# honu_dev 제작 틀

honu_dev 채널의 카드뉴스와 릴스를 같은 디자인으로 다시 만들기 위한 틀입니다.

## 이 계정의 목표

**채널 주인이 만든 앱(지금은 필덕)이 자연스럽게 노출되는 것. 단, 광고처럼 보이면 안 된다.**

- 앱을 직접 홍보하지 않는다. 쓸모 있는 콘텐츠로 사람을 모으고, 궁금해진 사람이 프로필에서 앱을 발견하게 한다.
- 그래서 대부분의 콘텐츠는 앱과 상관없이 그 자체로 저장하고 싶을 만큼 쓸모 있어야 한다. 쓸모가 곧 신뢰이고, 신뢰가 있어야 앱도 믿고 눌러 본다.
- 앱이 나오는 콘텐츠는 릴스에서만, 일주일에 두 개까지, 채널 주인이 직접 말한 경험으로만 만든다. 앱은 이야기 속 결과물로 잠깐 보이고, 부탁은 "앱은 프로필에 있어요" 한 줄을 넘지 않는다.
- 카드뉴스에는 채널 주인의 이야기와 앱을 넣지 않는다.
- "다운로드", "지금 설치", "링크 클릭", 할인·혜택 같은 광고 말투는 어디에도 쓰지 않는다.

## 공통 스타일

- 캐릭터: 연한 파랑 픽셀 슬라임 (16×14 격자, 기본 얼굴은 검정 세로 눈 두 개(반짝임 없음). 표정은 반짝(눈에 흰 점)·놀람·신남·웃음 4가지이고 특별한 순간에만 쓴다)
- 말투: 친근한 존댓말, 과장 금지, 숫자는 사실만
- 부탁은 한 게시물에 하나만 (저장 또는 공유)
- 해시태그는 5개 이하

## 출처를 쓰는 법 (카드뉴스·릴스 공통, 반드시 지킨다)

- 써도 되는 것: 공식 발표와 공지에 나온 사실(출시일, 기능, 가격, 정책). 출처 이름과 날짜를 적는다.
- 남의 글 하나(기사, 블로그, 경험담, 커뮤니티 글, 영상)를 콘텐츠의 몸통으로 삼지 않는다. 장면이나 전개를 순서대로 옮기면 표현을 바꿔도 안 된다.
- 개인의 경험담이나 에세이는 일반적인 조언을 설명하는 예시로 한 번만, 한두 문장으로 언급한다. 본문의 주인공은 조언이지 그 사람의 이야기가 아니다.
- 일반인의 실명을 쓰지 않는다. "한 1인 개발자", "한 시민기자"처럼 쓴다. 남의 실패를 제목이나 표지의 미끼로 쓰지 않는다.
- 소재가 글 하나에만 기대고 있어서 위 방식으로 풀 수 없으면 만들지 않고, Notion 항목 메모에 "글 하나에 의존, 허락 필요"라고 적은 뒤 다음 소재로 넘어간다.
- 입력이 "직접"인 소재(채널 주인이 직접 말한 경험)는 출처 주소가 없어도 된다. 메모에 "[채널 주인이 직접 말한 사실]"로 적힌 내용만 "저는 ~했어요"로 쓸 수 있고, 거기에 없는 경험·숫자·감정은 보태지 않는다.
- 필덕(채널 주인의 앱) 이야기가 나오는 콘텐츠는 릴스와 카드뉴스를 합쳐 일주일에 두 개까지만 만든다. 앱은 이야기 속 결과물로 보여 주고, 부탁은 마지막 한 줄 "앱은 프로필에 있어요"를 넘지 않는다. 건강 효과는 말하지 않고 알림·기록 기능만 말한다.
- 메모에 "자동 작업은 고르지 말 것"이라고 적힌 소재는 건너뛴다.
- **카드뉴스에는 채널 주인의 이야기를 쓰지 않는다.** 입력이 "직접"인 소재, 채널 주인의 경험담, 필덕을 비롯한 채널 주인의 앱 이야기는 카드뉴스로 만들지 않는다. "저는 ~했어요" 같은 1인칭 경험 문장도 쓰지 않는다. (릴스는 채널 주인이 매일 직접 검수하므로 위 규칙대로 쓸 수 있다)
- **기사·블로그·영상의 표현은 가져오지 않는다.** 사실(무엇이, 언제, 얼마나)만 가져오고 문장은 처음부터 새로 쓴다. 원문과 열 글자 넘게 같은 구절이 있으면 고친다. 기자나 글쓴이의 의견, 비유, 제목은 옮기지 않는다.
- 꼭 필요한 인용은 한 게시물에 한 문장까지만, 따옴표와 출처 이름을 붙여 쓴다.
- 기사에 실린 사진, 그래프, 캡처 화면은 쓰지 않는다. 그림은 틀로 직접 만든다.
- 소식은 언론 기사보다 회사의 공식 발표·공지·문서를 출처로 삼는다. 기사밖에 없으면 사실을 두 곳 이상에서 확인한 뒤 쓴다.
- 숫자는 출처에 있는 그대로만 쓰고, 요금제·사용량처럼 바뀌기 쉬운 조건에는 날짜를 함께 적는다.

## 카드뉴스 (`cardnews/`) — 모든 카드뉴스는 모션 카드뉴스로 만든다

- 크기 1080×1350(4:5), 9장 구성. 한 장이 5초짜리 영상이다(처음 2.5초 안에 다 나타나고 나머지는 읽는 시간). 릴스와 같은 세계(픽셀 구름, 슬라임, 노란 숫자 블록)를 쓴다.
- 위쪽: 배경 테마 + 대화창이 움직이는 영역. 아래쪽: 밝은 크림 바탕에 작은 슬라임 무늬, 그 위에 번호·제목·설명
- 색·크기·위치·그림자·움직임은 전부 `project/card.css` 에 있다. 이 파일은 고치지 않는다.
- 만드는 법 (`cardnews/` 폴더에서)
  1. `project/*.html` 의 글자만 바꾼다
  2. `node render.js` → `shots/01.png …` 정지 그림(영상의 마지막 모습). 전부 열어 글자가 넘치거나 겹치지 않는지 확인한다
  3. `node render.js --video` → `shots/01.mp4 …` 올리는 영상. 9장에 1분쯤 걸린다
  4. 배경을 바꾸려면 두 명령 모두에 `--theme=이름` 을 붙인다. 안 붙이면 노을(sunset)
- 배경 테마: 노을(기본), `sun` 노랑, `coral` 코랄, `pink` 핑크, `orange` 오렌지, `lav` 라벤더, `grid` 모눈종이, `night` 남색, `forest` 진녹색
  - 한 게시물 안에서는 한 가지 테마만 쓴다. 직전 게시물과 다른 테마를 고르고, 어떤 테마를 썼는지 Notion 메모에 적는다(나중에 성과 비교용)
- 장 종류
  - `Main.html` 표지: 큰 제목 3줄 이내 + 한 줄 설명 + 기울어진 대화창(보낼 말 3개)과 슬라임
  - `S2.html` 왜 봐야 하는지: 제목 + 흐린 창(막연하게 말하면)과 또렷한 창(이렇게 바꾸면)의 대비
  - `S3~S7.html` 본문: 위쪽 대화창(내가 보내는 말 + AI의 짧은 답) / 아래쪽 번호·상황·제목 2줄·설명 2줄
  - `S8.html` 한눈에 보기: 체크 목록 5줄(차례로 체크됨)
  - `S9.html` 마무리: 큰 슬라임 + 저장 유도 한 가지 + `@honu_dev`
- 본문 장을 쓸 때
  - 주인공은 대화창이다. "이렇게 하세요"를 글로 설명하지 말고, 실제로 보낼 말을 말풍선에 넣는다
  - 내가 보내는 말: 4줄 이내, 한 줄 13자 안팎. 핵심 구절 하나만 `<mark>` 로 감싼다(형광펜이 그어짐)
  - AI의 답: 굵은 첫 줄 + 1~2줄. 한 줄 17자 안팎. 지어낸 예시이므로 특정 제품의 실제 답처럼 보이게 쓰지 않는다
  - 제목 2줄(각 10자 안팎), 설명 2줄. 설명 중 핵심 한 줄만 `<em>` 으로 감싼다(파랑)
  - 아래 진행 표시(`.prog`)는 장 순서에 맞게 `class="on"` 개수를 맞춘다
  - 태그에 붙은 `class="pop"`, `class="up"`, `style="--d:…"`, 슬라임(`.slime`) 부분은 움직임 설정이다. 지우거나 바꾸지 않는다
  - 슬라임은 기본 표정(검정 눈)이 원칙이다. 특수 표정은 그 표정을 지을 만한 정보가 나오는 순간에만, 한 장에 한 번, 1.3초쯤만 쓴다. 표지와 마무리는 기본 표정만 쓴다
  - 본문 장은 AI 답이 나오는 순간(1.8~3.1초)에 표정이 한 번 바뀐다. 장 내용에 맞게 `.face` 덩어리를 `project/faces.txt` 의 조각(반짝·놀람·신남·웃음)으로 바꾸고, 맞는 표정이 없으면 지운다. 다섯 장이 모두 같은 표정이 되지 않게 한다
- 대화 형식이 안 맞는 주제(소식, 비교 등)도 위쪽 창 안의 내용만 바꾼다. 창 안에는 짧은 목록이나 큰 숫자 한 줄을 넣을 수 있다. 새로운 배치는 만들지 않는다
- 화살표, "넘겨보기", 가운뎃점으로 이은 문구, 영어 대문자 꼬리표는 넣지 않는다
- 장 수가 바뀌면 `render.js` 의 목록과 각 장의 쪽수 표시를 맞춘다
- 만든 `01.mp4 …` 와 `01.png …` 를 `cardnews/<날짜>-<주제>/` (초안은 `drafts/…`)에 올린다. 영상은 올리는 용도, 그림은 Notion에서 검수하는 용도

## 릴스 (`reel/`)

틀은 하나로 고정: **훅 → 1단계 → 2단계 → 3단계 → 마무리** (약 19초). 장면 코드는 고치지 않고 문구 파일(JSON)만 새로 쓴다.

- 소재를 고를 때와 쓸 때는 위의 "출처를 쓰는 법"을 따른다(특히 "직접" 소재와 필덕 이야기 규칙)
- 크기 1080×1920, 30fps, 음악 없음 (음악은 올릴 때 직접 추가)
- 색: 하늘색 바탕, 노랑 블록, 빨강 강조. 캐릭터와 위치는 틀에 고정
- 글꼴: 갈무리11(픽셀 글꼴, `reel/fonts/`). 단계의 설명 한 줄(`note`)은 마지막 박스 바로 아래 노란 띠로 나온다
- 만드는 법 (`reel/` 폴더에서)
  1. `example.json` 을 복사해 문구만 바꾼다
  2. `python3 make_reel.py 내문구.json stills` → `out/<slug>/still_0~5.jpg` 로 미리보기 확인
  3. `python3 make_reel.py 내문구.json` → `out/<slug>/reel.mp4`
- 문구 파일 구성
  - `slug`: 영어 소문자와 `-` 로 된 짧은 이름
  - `hook`: `line1`(검정), `line2`(빨강), `badge`(노랑 띠, 선택). `images` 는 선택(앱 화면 등 1~2장, 없으면 슬라임이 크게 나옴)
  - `steps`: 정확히 3개. 각 단계는 `title1`, `title2`, `boxes`(1~3개), `note`
    - 박스: `text`, 선택으로 `tone`(white/blue/red/green), `check`(true 면 초록 체크)
  - `cta`: `line1`, `line2`, 선택으로 `small`
- 표정 (`mood`, 선택): `hook`, 각 단계, `cta` 에 넣을 수 있다. 안 넣으면 기본 표정
  - `base` 기본 / `glint` 반짝(관심이 생겼을 때, 좋은 팁) / `surprise` 놀람(의외의 사실, 흔한 실수) / `excited` 신남(희소식, 해결됐을 때) / `smile` 웃음(마무리)
  - 단계 장면에서는 마지막 박스가 나온 뒤에만 표정이 바뀐다 (반응처럼 보이게)
  - 특별한 표정은 영상 하나에 최대 두 장면만 쓴다. 내용과 맞을 때만 쓰고, 맞는 장면이 없으면 전부 기본으로 둔다
- 글자 수 기준 (넘으면 자동으로 조금 줄이고, 그래도 넘치면 오류로 멈춤)
  - 훅 두 줄: 각 9자 안팎, 띠: 14자 안팎
  - 단계 제목 두 줄: 각 10자 안팎
  - 박스: 18자 안팎(체크가 있으면 14자), 설명 한 줄: 16자 안팎
  - 마무리 두 줄: 각 11자 안팎
- 완성한 영상은 `drafts/<날짜>-<slug>/reel.mp4` 로 올린다
