# reel-free: 슬라임만 고정하고 매일 새로 짜는 릴스

채널 주인 결정(2026-11-22): "틀을 주는 게 아니라 최소한의 틀로 창의력을 이끄는 게 더 나은 결과물을 준다."
그래서 릴스는 정해진 화면에 문구를 채우지 않는다. 아래 **고정하는 것**만 지키고, 장면 구성·소품·모션·전환은
그날 내용에 맞춰 HyperFrames 화면을 처음부터 짠다. `example/index.html` 은 첫 시안(애플 개발자 등록, 15초)으로,
구조와 기술 규칙을 보여 주는 예시다. 그대로 베끼지 말고 그날 내용에 맞는 장면을 새로 만든다.

## 고정하는 것 (최소한의 틀)

1. **슬라임과 표정 15가지**: 그림은 `../reel/make_reel.py` 에서만 가져온다(`kit.py` 가 `project/slime/<표정>.png` 로 뽑아 준다).
   새로 그리거나 색·모양을 바꾸지 않는다. `image-rendering:pixelated` 로 키운다. 영상 처음부터 끝까지 화면에 있다(뛰어나가며 장면을 넘기는 순간은 예외).
   표정은 `../README.md` 의 "슬라임 표정" 표에서 내용에 맞게 고른다. 기본은 `base`, 특수 표정은 그럴 만한 순간에만.
   한 영상에서 여러 표정을 골고루 쓰고 같은 특수 표정을 되풀이하지 않는다. 움직임(튀기, 찌그러짐, 뛰어나가기 등)은 자유.
2. **slimebot.ai 표시**: 왼쪽 위(left 64px, top 150px), 슬라임처럼 칸칸이 찍힌 **도트 글자**. 계정 이름이 2026-11-24 tenbylabs 에서 slimebot.ai 로 바뀌었다. TENBY LABS 라고 쓰지 않는다.
   2026-11-24 채널 주인: "좌상단 아이디를 픽셀스럽게." → `example/index.html` 의 `<svg class="brand" ...>` 와 `.brand` 스타일을 **그대로 복사**해 쓴다
   (글꼴이 아니라 1칸=4px 사각형으로 그린 그림이라 3번 글꼴 규칙과 부딪히지 않는다). 글자를 Pretendard 로 되돌리거나 도트 모양·색을 바꾸지 않는다.
3. **글꼴**: Pretendard(`project/fonts/`)만 쓴다. 외부 글꼴·웹 주소를 불러오지 않는다.
4. **자막**: 화면 위쪽(대략 top 220~620px), 굵은 글씨(800~900), 1~2줄. 핵심어 하나만 색으로 강조한다.
   한 문장을 2~3화면에 나눠 실어도 된다. 자막 한 줄은 가로 960px 안에 들어가야 한다.
5. **45초 이상, 1080x1920, 30fps**. 시간을 늘려 채우지 않는다. 내용이 모자라면 더 조사해서 장면을 더한다.
6. **사실 확인 규칙과 문장 검토**: 예약 작업 프롬프트의 규칙 그대로. 화면에 나오는 모든 숫자·조건·이름은 확인한 것만.

## 소리 (2026-11-22 채널 주인 결정)

배경음과 효과음은 `music.py` 로 코드로 직접 만들어 영상에 넣는다(저작권 걱정 없음).
- 배경음 기준: 채널 주인이 고른 큐트 카와이 로파이(Heart Bubbles, 지금까지 릴스에 쓴 lemonade·chocolate milk·pudding·hungry cat·silly dog·ditto). 2026-11-23 그 곡들을 측정한 값: 빠른 박 130~150(드럼은 절반 속도), 1초에 3.4~4.9번 촘촘한 타격, G·D장조 중심, 100Hz 아래 저음 25~50%·300Hz~1kHz 중음이 두툼, 고음은 적음. 채널 주인 피드백: "축축 처지면 안 된다", "효과음과 멜로디가 엉키면 안 된다"(효과음은 배경음 조를 따르고, 그 자리 멜로디는 쉰다).
- 남의 곡을 베끼지 않는다. 멜로디는 영상마다 seed(slug)로 새로 만들어진다.
- 분위기(`--mood`)를 그날 내용에 맞게 고른다: `calm`(차분한 설명·정리), `bright`(기본, 꿀팁·출시 상식), `playful`(신나는 소식·추천 모음), `focus`(주의할 점·정책 변경).
- 효과음은 화면에서 일어나는 일에 시각을 맞춘다. 장면을 짜면서 `out/events.json` 에 `[[초, "종류"], ...]` 로 적는다(종류는 music.py 맨 위 설명). 효과음이 날 때 배경음이 저절로 살짝 줄어든다. 모든 움직임에 넣지 말고 눈에 띄는 순간(착지, 도장, 숫자, 체크, 전환, 마무리)에만 넣는다.
- 채널 주인이 "음악이 별로"라고 하면 그 말을 이 칸에 규칙으로 더한다.
- 2026-11-23 채널 주인: "배경음을 조금 더 줄이자, 거슬린다." → `music.py` 배경음 크기를 RMS -16dBFS에서 -22dBFS로 낮췄다(효과음 크기는 그대로). 배경음 크기를 다시 올리지 않는다. `--music-only` 등으로 따로 키우거나 ffmpeg 에서 볼륨을 올리지 않는다.

## 나레이션 (2026-11-24 채널 주인 결정)

- 나레이션 목소리는 **구글 TTS `ko-KR-Chirp3-HD-Despina`**(여성)로 한다. 2026-11-24 채널 주인 확정("algenib 보단 despina 가 낫다").
  (잠깐 Algenib 로 바꿨던 것은 채널 주인이 Algenib 를 타입캐스트 "필재"로 혼동한 것이었다. 필재는 타입캐스트 목소리라 구글엔 없다.)
  다른 목소리로 바꾸지 않는다.
  (처음엔 타입캐스트 "필재"였으나 2026-11-24 타입캐스트 무료 계정이 UNUSUAL_ACTIVITY_DETECTED 로 막혀 바꿨다. 무료 플랜은 상업 이용도 안 된다.)
- 만드는 법: 영상(`reel.mp4`)과 `events.json`, `narration.json` 을 초안 폴더에 둔 뒤
  `python3 templates/reel-free/narrate.py drafts/<날짜>-reel-<slug>` → 같은 폴더에 `reel_narrated.mp4`, `narration_result.json`.
  기본이 구글 Despina 다. 타입캐스트로 만들 때만 `--engine typecast` 를 붙인다. `narration.json` 형식은 `narrate.py` 맨 위 설명 그대로.
- 숫자는 "이천오백 개"처럼 읽혀야 한다(2026-11-24 채널 주인: "2,500개를 '이 오백 개'로 읽는다"). `narrate.py` 가 음성으로 보낼 때만 천 단위 쉼표를 뺀다(`2,500` → `2500`). 자막의 숫자 표기는 그대로 둔다.
- 문장은 장면 길이에 맞게 짧게 쓴다. `narration_result.json` 의 `overflow_sec` 가 0.3초를 넘는 줄은 문장을 줄여 다시 만든다.
- 키는 Default 환경의 네트워크 시크릿(texttospeech.googleapis.com, X-Goog-Api-Key)이 자동으로 붙인다.
- API 키는 어디에도 적지 않는다(작업 지시문, 저장소, Notion, 대화 모두).

## 매일 새로 만드는 것

배경, 색, 장면 구성, 소품(카드, 도장, 숫자, 진행 막대, 타임라인, 저장소 카드, 속보 띠 등), 모션, 전환.
소재 종류에 따라 이야기 방식도 고른다. 예:
- 절차·조건(출시 상식, 정책): 카드·도장·체크리스트·숫자 강조 (example 참고)
- 쇼케이스(인기 레포, 스킬·MCP 추천): 저장소 카드가 한 장씩 넘어오고 확인한 별 개수가 올라감
- 소식(새 기능, 업데이트): 바뀌기 전/후 비교, 속보 띠
- 프롬프트·질문 요령: 대화창(흔한 질문 → 고친 질문). 대화형은 이 경우에만 쓴다.

### 참고 모션 (채널 주인이 보낸 레퍼런스에서 뽑은 움직임과 리듬)
남의 영상·캐릭터·디자인을 그대로 따라 하지 않는다. 움직임과 리듬만 참고한다.
- 2~3초마다 장면이 바뀐다. 한 장면에 생각 하나. 시간 끄는 장면(3초 넘게 멈춘 화면)이 없다.
- 훅을 세 번에 나눠 쌓기. 마지막 줄을 크게, 핵심어 색 강조.
- 소품(아이콘)이 슬라임 주위로 터지듯 퍼짐.
- 긴장 한 박자: 놀람 표정 + "!" 
- 둘로 나눠 비교(카드 두 장, 컬러 vs 회색으로 상태 표시).
- 슬라임이 뛰어나가며 장면을 넘김(화면이 함께 쓸려 나감).
- 스포트라이트 + 큰 숫자가 올라가는 장면, 진행 막대.
- 경고 배지가 튀어나오고 한 구간이 빨갛게 표시됨.
- 말로 하는 동작을 화면에서 그대로 보여 주기(예: 가로 카드가 세로로 돌아감).
- 도장이 크게 날아와 찍히고 화면이 살짝 흔들림.
- 체크리스트에 차례로 체크, 마지막에 화면이 확 다가감(줌인).
- 커서가 움직이며 클릭, 카드가 미끄러져 들어옴. 큰 숫자 하나만 띄우는 장면.

### 레퍼런스에서 가져온 것 (2026-11-24 채널 주인 결정)
채널 주인이 보낸 "이번 주 깃허브 탑텐" 릴스(다른 계정)에서 방식만 가져온다. 그 계정의 색 조합(베이지 바탕·검은 카드·주황), 마스코트, 주차 표기 디자인, 문구는 가져오지 않는다. 우리 것은 슬라임과 그날 새로 짠 색으로 만든다.
- **하는 일을 화면으로 보여 주기**: 저장소·도구·기능을 소개할 때 설명 글을 적은 카드 대신, 그것이 하는 일을 보여 주는 작은 가짜 화면을 그린다. 예: 영상 편집 도구 → 편집 타임라인에 자막 줄이 생김, 브라우저 도구 → 브라우저 창에서 커서가 저절로 움직이며 클릭, 채팅 규격 → 채팅창에 말풍선이 오감, 코드 검사 → 코드 줄에 빨간 표시가 붙음. 가짜 화면 안 글자도 34px 이상. 실제 회사 로고·실제 앱 화면을 베끼지 않고 단순한 도형으로 그린다.
- **제목은 "무엇을 해 주는지" 한 줄**: 이름보다 먼저, 그것이 해 주는 일을 짧게(예: "영상 자르기와 자막") 쓰고 핵심 낱말 하나만 색을 바꾼다. 이름(영문)은 그 아래 고정폭 글꼴로.
- **진행 표시를 계속 띄우기**: 여러 항목을 소개하는 릴스는 화면 한쪽에 "3/4"처럼 지금 몇 번째인지 보여 주는 작은 칸을 끝까지 띄운다. 장이 바뀔 때 숫자가 올라간다. 순위면 아래 순위부터 1위로 세어 올라간다(1위를 마지막에).
- **이야기로 여는 훅**: 훅은 "숫자 + 이상한 점"으로 연다(예: 오래 조용하던 것이 갑자기 1위, 지난주 목록이 거의 다 바뀜). 그 숫자를 보여 주는 그래프·표를 첫 장면에 함께 그린다. 확인한 숫자만 쓴다.
- **인기 레포는 "이번 주에 받은 별"**: 공개된 주간 순위 자료에서 그 주에 받은 별 수를 확인할 수 있으면 그것을 쓰고(기준 날짜 함께), 확인할 수 없으면 전체 별 수를 "전체 ★"로 분명히 적는다. 둘을 섞지 않는다.
- **시리즈로 잇기**: 인기 레포처럼 매주 다루는 주제는 지난번 우리 릴스와 비교하는 한 장면을 넣을 수 있다(예: 지난번에 소개한 것 중 이번에도 남은 것). 비교는 우리 drafts 의 지난 reel.json 에 적힌 것만 근거로 한다.
- **마무리에 행동을 그림으로**: 마지막 장면에서 저장 버튼을 누르는 모습을 짧게 그린다(부탁은 여전히 하나, 저장).
- 항목당 5~7초. 항목이 많아져도 장면마다 새로 알게 되는 것이 있어야 하고, 45초 이상 규칙은 그대로다.

### 레퍼런스에서 가져온 것 2 (2026-11-25 채널 주인이 보낸 "AI 티 지우기 스킬" 릴스)
다른 계정 영상이다. 방식만 가져오고 그 영상의 색·화면·문구·도구 이름은 가져오지 않는다. 그 영상은 27초지만 우리는 45초 이상 규칙과 위쪽 자막 규칙을 그대로 지킨다.
- **첫 2초에 전/후를 한 화면에서**: 도구·기능 소개 릴스는 첫 장면에 "고치기 전"과 "고친 뒤"를 가르는 세로 막대가 좌우로 움직이며 두 화면을 번갈아 보여 준다. 무엇이 좋아지는지 말보다 먼저 눈으로 보이게 한다. 두 화면 모두 우리가 단순한 도형으로 그린 가짜 화면이다.
- **끝에 줄 보상을 위에 붙여 두기**: 화면 맨 위에 얇은 띠를 끝까지 띄우고, 왼쪽엔 오늘 주제 한 줄, 오른쪽엔 "끝에 시작하는 법"처럼 마지막에 줄 것을 적는다. 약속한 것은 실제로 마지막 장면에 보여 준다(우리는 링크 대신 화면 속 명령 한 줄이나 메뉴 순서).
- **문제는 확대해서 짚기**: "이게 문제예요" 장면은 화면을 확 당겨(줌인) 문제 부분마다 흰 테두리나 빨간 핀을 차례로 찍고, 다시 빠진다.
- **단계는 이어진 칸으로**: 여러 단계를 거치는 기능은 "간격 → 색 → 글씨"처럼 칸을 한 줄로 늘어놓고 지금 단계 칸에 불이 옮겨 가게 한다. 큰 숫자(예: 체크리스트 개수)는 목록이 빠르게 내려가는 화면 위에 띄운다. 숫자는 확인한 것만.
- **중간에 "근데 덤이 있어요"**: 뒤쪽 3분의 1쯤에서 한 번, 숨은 기능이나 덤을 꺼내 관심을 다시 붙든다. 덤도 확인한 사실이어야 한다.
- **마지막은 대비 한 줄 + 실제 시작 화면**: "직접 하면 오래 / 이건 바로"처럼 대비를 한 줄로 보여 주고, 터미널이나 앱 화면에 시작 명령이 타자 치듯 찍힌다. 시간·비용 같은 대비 숫자는 공식 출처로 확인될 때만 쓰고, 없으면 숫자 없이 쓴다.
- **나레이션과 자막을 나눠 쓰기**: 나레이션은 말하듯 짧은 문장("딱 보면 AI죠?")으로 풀고, 자막은 그 문장의 핵심 낱말만 크게 줄여 쓴다. 자막이 바뀌는 시각을 나레이션 문장 시작에 맞춘다.

### 레퍼런스에서 가져온 것 3 (2026-11-25 채널 주인이 보낸 "투자자 따라 하는 Claude 스킬" 릴스)
레퍼런스 1과 같은 계정(베이지 모눈 바탕·주황·픽셀 마스코트)으로 보인다. 그 계정의 색·마스코트·문구는 가져오지 않는다. 방식만 가져온다.
- **훅은 "누구처럼 + 무엇을 안 해도 됨"**: 널리 아는 이름이나 상황 하나와, 보는 사람이 덜게 되는 수고를 한 문장에 담는다. 첫 장면에서 그 일이 실제로 일어나는 가짜 화면(고르기 → 그대로 복사됨 → 체크 도장)을 보여 준다.
- **"하나인 줄 알았는데 여러 개" 펼치기**: 도구 하나를 소개하다가 그 안에 든 기능 개수를 밝히는 순간, 아이콘 하나가 여러 개로 갈라지며 튀어나온다. 개수는 공식 문서·저장소에서 확인한 것만.
- **가장 센 기능은 뒤로 아껴 두기**: 기능을 여럿 소개할 때 가장 흥미로운 하나는 뒤쪽 3분의 2 지점에 두고 "제일 놀라운 건"으로 꺼낸다. 앞쪽은 기본 기능부터.
- **기능마다 그 기능이 일하는 장면**: 터미널에 글자가 찍히고, 알림 띠가 쌓이고, 막대가 상한선에서 멈추며 도장이 찍히는 식으로 2~4초짜리 작은 화면 하나씩. (레퍼런스 1의 "하는 일을 화면으로 보여 주기"와 같다)
- **마무리 전에 안심 한 장면**: 돈·계정·파일을 건드리는 도구는 "내가 승인해야만 실행"처럼 안전장치를 한 장면 보여 준 뒤 시작하는 법으로 넘어간다. 안전장치도 공식 문서로 확인한 것만.
- **시작하는 법은 동작으로**: "저장소 주소 복사 → Claude 입력창에 붙여 넣기 → 한 줄 입력"을 커서가 실제로 하는 모습으로 보여 준다(글로 설명하지 않는다).
- **슬라임은 내내 구석에서, 끝에는 가운데로**: 본론에서는 슬라임이 화면 구석에서 소품을 가리키거나 반응하고, 마지막 장면에서 가운데로 뛰어나와 부탁(저장)을 한다.
- 이 영상의 "댓글로 낱말 남기면 안내를 보내 드려요" 마무리는 쓰지 않는다(부탁은 저장 하나, 링크·DM 안내 없음 규칙). 바꾸려면 채널 주인이 정한다.

### 레퍼런스에서 가져온 것 4 (2026-11-25 채널 주인이 보낸 "오르카 봇" 릴스, 한국어 AI 소식 채널)
그 채널의 색(베이지 모눈·주황)·마스코트·채널 이름·문구는 가져오지 않는다. 방식만 가져온다.
- **사건으로 여는 훅**: 도구 설명이 아니라 그 도구에 얽힌 실제 사건 하나로 연다(예: 저장소가 갑자기 숨겨짐, 하루에 수백 건). 사건과 숫자는 공식 발표·저장소·믿을 만한 보도로 확인한 것만 쓴다. 확인 못 하면 쓰지 않는다.
- **위쪽 두 칸 표시**: 화면 위 왼쪽에 "// 01 · 숨겨진 저장소"처럼 지금 장 번호와 짧은 장 이름, 오른쪽에 "사례 1/3"처럼 그 장 안의 진행을 띄운다. 장이 바뀔 때 숫자가 올라간다(레퍼런스 1의 진행 표시를 장 단위로 넓힌 것).
- **"써 본 사람들" 묶음**: 기능 설명 뒤에 실제로 써 본 사례 2~3개를 "사례 0/3 → 1/3 …"으로 센다. 사례는 출처(공식 블로그·영상·글)를 확인할 수 있는 것만, 화면에 출처 이름을 작게 적는다. 출처가 개인 글 하나뿐이면 쓰지 않는다.
- **익숙한 물건으로 숫자 보여 주기**: 날짜는 일력이 넘어가게, 시각은 시계 바늘이 돌게, 값은 영수증이 출력되며 "합계 0원"이 찍히게. 요금은 공식 요금표로 확인한 것만.
- **주의할 점은 토글로**: 권한·보안 주의는 설정 화면의 스위치가 꺼짐에서 켜짐으로 바뀌는 장면으로 보여 준다(레퍼런스 3의 안심 장면과 같은 자리).
- **같은 날 카드뉴스로 넘기기(검토 중)**: 그 영상은 "자세한 사용법은 카드뉴스로"로 끝난다. 우리는 릴스와 카드뉴스 주제가 다르니 지금은 쓰지 않는다. 채널 주인이 같은 주제로 묶기로 정하면 그때 쓴다.

### 레퍼런스에서 가져온 것 5 (2026-11-26 채널 주인 요청: 인기 릴스 20개 모션 모음)
레퍼런스 1·3·4와 같은 한국어 AI 소식 채널의 조회수 상위 20개를 장면 캡처로 봤다. 자세한 목록은 `references/2026-11-26-top20-motions.md`. 그 채널의 색·마스코트·카드 디자인·문구는 가져오지 않는다. 우리가 새로 쓸 만한 것:
- **자막 칩이 낱말 단위로 자람**: 위 자막이 나레이션에 맞춰 낱말씩 늘어나고 문장이 끝나면 새로 시작한다.
- **숫자는 매달린 태그로 카운트업**: 물체 모서리에 줄로 매달린 태그가 흔들리며 숫자가 올라간다. 가격은 올라가다 취소선 → 0원 도장.
- **순위 줄이 위로 올라가 붙기 / 그래프 끝 막대만 솟기 / 1P vs 2P 막대 대결**: 순위·급상승 훅에 쓴다.
- **개수는 쏟아지는 아이콘으로**: 아이콘·얼굴이 격자를 채우며 숫자가 따라 오른다. 분량은 서류가 쌓여 올라가는 기둥으로.
- **장마다 배경 색 전체를 바꾸고, 60~70% 지점에 검은 바탕 반전 구간 한 번**.
- **하나의 기기 프레임 안에서 이야기 진행**: 폰·모니터 프레임은 고정, 속 화면만 바뀌고 물건은 포물선으로 기기 사이를 난다.
- **동시성은 여러 커서·지하철 노선 갈래로, 고르기는 이정표·지도로, 비교는 같은 화면 9장 격자로**.
- **전환은 대각선 점무늬 띠가 쓸고 지나가기**, 큰 순위 숫자는 배경에 크고 흐리게.

## 기술 규칙 (HyperFrames가 프레임마다 정확히 찍기 위해)

- `project/index.html` 하나. 루트 `<div id="root" data-composition-id="main" data-start="0" data-duration="<초>" data-width="1080" data-height="1920" data-fps="30">`.
- 움직임은 GSAP 타임라인 하나(`gsap.timeline({paused:true})`)에 모두 넣고 `window.__timelines["main"] = tl` 로 등록한다.
  CSS animation, setTimeout, requestAnimationFrame, Math.random, Date 는 쓰지 않는다(같은 입력이면 같은 영상이 나와야 한다).
  시각에 따라 바뀌는 것(표정, 숫자)은 타임라인 `onUpdate` 에서 현재 시각으로 계산해 그린다(`example` 의 setMood 참고).
- 그림·글꼴은 `project/` 안의 파일만. 외부 주소, 남의 이미지, 로고, 사진을 넣지 않는다. 아이콘은 SVG 픽셀 도형으로 직접 그린다.
- 화면 안전 영역: 글자는 가로 60~1020px, 세로 140~1560px 안에. 아래 360px 와 오른쪽 120px 는 인스타 버튼·설명이 덮으므로 중요한 글자를 두지 않는다.
- 글자 크기: 자막 84px 이상, 카드·소품 안 글자 34px 이상.
- 출처 표시: 화면 어딘가(위쪽 오른쪽 등)에 확인한 공식 문서 이름과 "YYYY-MM-DD 확인"을 작게 넣는다.

## 순서

```
cd templates/reel-free
npm ci
python3 kit.py                      # project/ 준비 (--example 을 붙이면 예시를 project/index.html 로)
# project/index.html 을 그날 내용으로 새로 쓴다
npm run lint                        # HyperFrames 검사: 0 errors 여야 한다
npm run render                      # out/reel.mp4
python3 check.py out/reel.mp4       # 자동 점검 + out/check_*.png 를 전부 Read 로 열어 눈으로 확인
python3 music.py --dur <영상 길이> --mood <분위기> --seed <slug> --events out/events.json --out out/audio.wav
ffmpeg -y -i out/reel.mp4 -i out/audio.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -shortest out/reel_sound.mp4
```
문제가 있으면 index.html 을 고쳐 다시 렌더한다. HyperFrames 가 두 번 실패하면 예전 틀(`../reel-long` 문구 파일 + `../reel-hf`)로 찍는다.

## 초안으로 올리는 파일

`drafts/<날짜>-reel-<slug>/` 에 `reel.mp4`(소리를 입힌 out/reel_sound.mp4), `index.html`(그날 화면 원본), `reel.json`, `events.json`(효과음 시각).
`reel.json` 에는 적어도 `{"slug", "source": [문서 이름, "YYYY-MM-DD 확인"], "hook": {"lines": [훅 세 줄]}, "scenes": [[시작 초, 장면에 나오는 글자 요약], ...], "music": {"mood": 분위기, "seed": slug}}`
를 적는다(저녁 "오늘 릴스 보내기" 작업이 `hook.lines` 를 읽는다). 슬라임 그림·글꼴·gsap·node_modules·out 은 올리지 않는다.
